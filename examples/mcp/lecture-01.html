先看一个画面

想象一个聪明的孩子，站在一屋子锁着的门前。

这个孩子就是 AI。门后是 GitHub、数据库、浏览器，或者公司的 API。孩子知道该做什么，却没有统一的开门方式——过去每扇门都有不同的把手、规则和说明书。

在这座桥出现之前

每个应用都要为每个工具单独编写连接器。换一个 AI 宿主，同样的集成工作就要重新做一遍。

聪明的适配器很多，共同语言几乎没有。

真正的问题

能不能让工具只描述一次自己的能力，却让许多 AI 应用都能理解？

先理解想法，再记缩写

一扇共享的门，比一串只用一次的钥匙更好。

Host

用户正在使用的 AI 应用。

Client

藏在 Host 里的连接器。

Server

对外提供工具或上下文的程序。

推导题 · 根据上面内容

为什么需要协议，而不是一堆一次性集成？

推导：好的回答应该连起复用、能力发现、权限控制，以及维护适配器的成本。

这不是面经原题。

试着说出来

30 秒面试回答

MCP 是一种开放协议，让 AI 应用可以用统一方式发现和使用外部工具与数据。以前每个 Host 都要为每个服务单独写集成；现在，MCP Client 把 Host 接到 MCP Server，Server 用共享的协议暴露能力。这样集成可以复用，但 Server 和它拥有的权限仍然需要被信任和审查。
插问仍然留在第 01 讲。说“下一讲”，我们再详细认识 Host、Client 和 Server。
